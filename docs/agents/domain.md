# 领域文档

工程技能探索本仓库前，应按以下规则读取领域文档。

## 探索前读取

- 读取根目录的 `CONTEXT.md`。
- 如果根目录以后出现 `CONTEXT-MAP.md`，改为根据其中的映射读取与任务相关的上下文文档。
- 读取 `docs/adr/` 中与待修改区域相关的 ADR。
- 如果这些文件不存在，静默继续，不要仅因缺失而建议提前创建。

`/domain-modeling` 会在领域术语或架构决策真正得到确认时按需维护这些文档。

## 文件结构

本仓库采用单上下文布局：

```text
/
├── CONTEXT.md
├── docs/
│   └── adr/
└── src/
```

## 使用词汇表中的术语

Issue 标题、重构方案、假设和测试名称应采用 `CONTEXT.md` 定义的领域术语，避免使用词汇表明确排除的同义词。

若所需概念尚未出现在词汇表中，应先判断是否正在发明项目并不使用的新术语；若确属领域缺口，再交由 `/domain-modeling` 处理。

## 标记 ADR 冲突

若拟议改动与现有 ADR 冲突，必须显式指出，不得静默覆盖：

> 与 ADR-0007 冲突——值得重新讨论，因为……
