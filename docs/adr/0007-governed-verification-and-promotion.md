# 验证、审查与提升是受治理的状态转换

SigmaCoder 使用风险分级动作审批和设计门、相对质量基线零回归、绑定 revision 的两级验证、策略要求时的 fresh-context 独立 Reviewer，以及对“应用提升”或“仅保留不可变包”的最终用户决定；无需 Reviewer 的 Task 在验证后直接进入包审批。任何新改动都会使旧验证、审查和批准证据失效；验证不可完成时只能通过限域、限版本、可审计的豁免产生 `COMPLETED_WITH_EXCEPTIONS`。该决定以部分自治速度换取专业团队可追责的质量和安全，模型不能自证完成、自行合入改动或把“仅保留包”表述为已提升。
